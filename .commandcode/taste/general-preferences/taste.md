- User gives terse directives and terse intermediate status check-ins (e.g., "continue", "done?", "whats the status", "quick proceed with finishing phase 1"); proceed autonomously through the implied work, and when checked in on mid-stream, give a concise done/not-done summary then keep forward momentum rather than lingering on blockers or asking permission to continue. Confidence: 0.7
- Deliver status reports as a single fenced ```text block with labeled sections (per-goal status, current build, runtime verification, remaining failures, verification gaps, files changed, fresh evidence). Confidence: 0.65
- Be honest about incompleteness: never declare a phase or goal complete until every mandatory acceptance criterion passes; keep unmet goals visibly unchecked with precise documented reasons. Confidence: 0.9
- In hot paths, replace modulo with a bitwise mask (`x & (n - 1u)`) when the divisor is a power of two, to avoid udiv/msub instructions. Confidence: 0.8
- Zero-overhead ("Δ=0") architecture philosophy: every OS path has a declared minimal baseline operation (direct MMIO store, bitmap pop, free-slot pop, naked branch to handler, raw kernel entry) and the implemented path must compile to the same instructions; hot paths use pre-bound static arenas with zero runtime allocation or bounds-checking; security invariants (W^X permissions, page-table freeze, CPU-die secret containment, DMA firewall, root of trust) are enforced at compile time, boot handoff, or hardware — never with runtime cycle cost; invariants for not-yet-built components are recorded as binding design constraints now and implemented with the first relevant driver. When stripping hot paths, only accounting counters and telemetry are removable — correctness/rejection checks that invariants or regression tests mandate (e.g., double-free rejection verified by an intentional double-free test) are essential and must stay, since removing them corrupts state. Confidence: 0.8
- Binary image discipline: `.bss` stays NOBITS (zero disk size in the image); the boot environment must deliver zeroed RAM before kernel entry (a boot-stub/bootloader contract, honored by the UEFI stub via an `.imgmeta` footer). Confidence: 0.85
