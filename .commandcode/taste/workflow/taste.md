# Workflow preferences

- Only fresh execution against the current source tree counts as verification; historical results are labeled historical and never cited as current evidence. Confidence: 0.9
- Never silently redefine or weaken requirement wording; when wording is ambiguous, record the precise verified property contract plus a clarification request (DECISIONS.md / KNOWN_FAILURES.md entries) and leave GOALS.md unchanged. Confidence: 0.9
- Preserve evidence artifacts (e.g., copy the QEMU serial log to kernel/qemu.log) and update the project-control docs (DECISIONS.md, KNOWN_FAILURES.md, VERIFICATION.md, CURRENT_STATE.md, Achieved Features.md) after verification work. Confidence: 0.85
- Verify reproducibility by two independent clean rebuilds and byte/hash comparison; record SHA-256 hashes in the artifact manifest. Confidence: 0.8
- Make tooling enforce completeness claims loudly (e.g., the image pipeline aborts the build if any linked object is unclaimed by a component class). Confidence: 0.7
- Report blocked work as BLOCKED with the specific environmental cause, and state explicitly when a substitute does not satisfy the goal (QEMU accounting alone does not satisfy a target-hardware measurement requirement). Confidence: 0.85
- Benchmark methodology: both sides of a latency comparison must be invoked identically (out-of-line calls on OS path and baseline; mark baselines `__attribute__((noinline))`) so call/ret overhead doesn't contaminate the delta; measure both directions of each operation (alloc and free); take min-of-N over many reps and attribute any residual to concrete code differences (lazy-init checks, redundant bounds checks, division ops), then trim them. Confidence: 0.85
- When the user adds new requirements or instructions, first deliver a triage assessment against already-built components — per-item compatibility status and change-size estimate (None/Tiny/Small/Medium) in a structured table or list with a bottom-line summary — before implementing anything. Confidence: 0.85
- When a new requirement conflicts with an existing design (e.g., freezing all page tables read-only vs. a runtime-created dynamic heap), surface the conflict explicitly with concrete options, a recommendation, and a decision request rather than choosing unilaterally. Confidence: 0.75
- Silent-hang diagnosis protocol: when the serial log goes quiet, launch QEMU with `-monitor tcp:127.0.0.1:<port>,server,nowait`, sample `info registers` repeatedly to catch the spinning PC, map it with `addr2line`/`objdump`, then add layered origin assertions (double-insert, orphan-remove, overlap, bounded walk, shadow-state tracker) to catch corruption at its first violation rather than theorizing from downstream symptoms. Confidence: 0.8
- Run build/QEMU steps one at a time instead of chained `start /b /wait` command chains — chains hide failures and leave stale processes that confuse later diagnosis. Confidence: 0.75
